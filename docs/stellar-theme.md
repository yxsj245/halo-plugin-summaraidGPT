# 星港导读与星枢领航员（4.0.7）

此版本为 theme-xiaozhu2.0 的前台星港风格增加可选适配，不替换插件在 Halo 后台的名称、Logo 或管理界面。原有风格和 AI 功能保持可用。

## 开启两条频道

安装新版插件 JAR 后，在 Halo 插件设置中保存以下两项：

| 位置 | 选项 | 作用 |
| --- | --- | --- |
| 摘要框样式设置 → UI 风格 | **星港导读**（`stellar`） | 摘要采用星港面板，洞察图谱同时跟随这套风格。 |
| RAG 智能助手 → 样式配置 → 配色方案 | **星港终端**（`stellar`） | 使用 SVG 领航员、新问答徽记、星港小窗与全屏会话。 |

两个开关独立，不会因为开启星港摘要而擅自改变助手身份。默认仍是插件原有简约摘要和暖白助手；本次不自动修改站点 ConfigMap。

摘要与图谱原有的启用/注入开关照常有效。关闭摘要 UI 不会阻止已启用图谱单独显示。问答是否可用仍由模型、RAG、Agent 和访问权限配置决定，样式开关不会开放权限。

## 新角色与用户侧名称

星港终端的悬浮角色为原创内联 **SVG 导航无人机**：切角舱体、双光学眼、中心星核、侧翼与轨道环。它不是精灵图，也不把现有宠物的地址直接换成一张 SVG 图片。

- 星港模式不下载 PetDex 精灵图、不启动逐帧动画计时器；即使旧图片失效，也能显示本地矢量角色。
- 待机为轻微悬浮和慢速轨道，悬停、思考、错误、拖动有对应形态；减弱动态效果时静态展示，状态标记保留。
- 点击、拖动、位置记忆、气泡和纯宠物模式保留。尺寸继续由 `petSize` 控制，位置按当前视口重新钳制。
- 星港模式覆盖前台宠物形象，后台已导入的宠物不删除；改回其他配色后仍使用原宠物。
- 问答头像和划词入口使用同源的「星核 + 导航轨道」徽记，支持主题昼夜变色。

用户侧名称使用 **星枢领航员**：

| 现有配置 | 星港模式表现 |
| --- | --- |
| 助手名称留空或为旧默认「智阅助手」 | 显示「星枢领航员」，欢迎语先按有效名称替换占位符。 |
| 站长填写其他名称 | 保留自定义名称。 |
| 头像留空或为默认插件图标 | 显示新 SVG 徽记。 |
| 站长填写自定义头像 | 保留；图片加载失败时回退徽记。 |
| 欢迎语/快捷问题/气泡仍为内置默认 | 切换为星港文案。 |
| 站长填写自定义文案或调整问题顺序 | 保留，欢迎语中的 `{assistantName}` 按有效名称替换。 |

这些映射发生在配置响应与前台展示中，不写回后台设置，不重写用户历史消息、模型名或 AI 回答。原默认摘要标题「文章摘要」显示为「本舱信号摘要」；站长自定义的「本文摘要」「AI 摘要」等仍保留。

## 昼夜、字体与降级

优先读取主题 `html[data-scheme="dark|light"]`，导航切换即时同步。显式站点状态优先于浏览器系统偏好；星港助手在站点没有该标记时，才按插件的 `colorMode`（浅色/深色/系统）降级。

- 主光与辅光：`--cyan`、`--violet`。
- 文字：`--text`、`--reader-text`、`--text-dim`。
- 面板：`--panel`、`--panel-soft`、`--panel-border`、`--hairline`、`--chip-bg`。
- 字体：中文正文复用 `--sans`；英文 HUD 复用 `--hud`；代码与元信息复用 `--mono`。没有第三款中文字体、外部 SVG 服务或新增字体下载。

样式封装在 Lit Shadow DOM，外部元素选择器不能直接覆盖组件内部，但 CSS 自定义属性可继承。变量缺席时组件采用回退口径，不代表其他主题会拥有完全相同的星港背景。

星港助手宿主层级为 `280`，高于正文/目录，低于主题装载和跃迁遮罩；不会在跃迁隧道上方露出问答窗口。非星港风格沿用原层级。

## 文章换舱与复制

摘要/图谱沿用插件的动态 DOM 挂载观察器，支持首页、分区、归档和检索入口搬入正文。配置请求期间再次换舱会补扫新占位，旧节点和迟到响应不再重新启动输出/轮询。本版本不修改主题跃迁脚本，也不创建新的覆盖层。

助手复制先尝试 Clipboard API；不安全 HTTP、API 缺席或权限拒绝时，再尝试临时文本域的旧式复制并清理节点、恢复输入焦点与选区。浏览器如果同时禁用两条通道，会明确提示手动选择文本，不假报成功。

## 安装与资源生效

1. 在 Halo 的插件管理中更新本地构建的 **4.0.7 JAR**（保持插件名 `summaraidGPT`）。
2. 确认插件与 AI Foundation 依赖正常启用，再在设置里选择上文两项星港风格。
3. 强制刷新前台页面。若仍显示旧宠物，核对 `/plugins/summaraidGPT/assets/static/RagAssistant.js` 是否来自新包、设置接口是否返回 `styleConfig.stylePreset = stellar`。
4. 摘要和图谱核对 `summaryConfig.uiStyle = stellar`。仅替换源码而未重建 bundle 不会生效；只刷新页面也不能修复宿主持续返回旧插件资源的情况，应重新加载新版插件资源。

### Windows 同版本上传报 500 的处理

如果当前站点已经安装应用市场的 `summaraidGPT 4.0.6`，不要再上传上次交付的同版本改造包。2026-10-05 的实际升级日志显示，Halo 将上传包复制到 `summaraidGPT-4.0.6.jar` 时遇到 Windows 文件占用（`FileSystemException`），前端因此显示「服务器内部发生错误，请稍候再试」。不是前台 SVG 或样式解析异常。

本地适配版已重新发布为 **4.0.7**，包内版本声明同步更新，Halo 会使用新的 `summaraidGPT-4.0.7.jar` 目标；不是只改下载文件名。请在现有插件的「升级」入口上传新包，保持插件名与配置不变。不要卸载插件或删除旧 JAR/配置，也不需要为这次同版本文件冲突重启 Halo。

本次没有替用户安装、重启 Halo 或调整真实站点设置。受控浏览器预览与实际安装效果分开记录。

## 开发验证

```powershell
# 前台局部测试优先
pnpm -C packages test -- tests/stellar-identity.test.ts tests/clipboard.test.ts tests/stellar-theme.test.ts

# 重建前台发行资源（拷回 static）
pnpm -C packages build

# Java 局部配置测试
.\gradlew.bat test --tests 'com.handsome.summary.endpoint.StellarStyleSupportTest' -x :packages:assemble -x :ui:assemble

# 最后完整打包
.\gradlew.bat build --no-daemon

# 既有 Halo + 受控插件/文章/AI 接口的浏览器验证
npx --package @playwright/cli playwright-cli -s=stellar-plugin open http://localhost:8090/
npx --package @playwright/cli playwright-cli -s=stellar-plugin run-code --filename packages/tests/stellar-browser-check.cjs
```

浏览器检查从插件根目录执行，使用当前主题资源，拦截插件脚本为本地构建产物，文章正文、摘要、图谱、配置与 AI 回答均为受控样本；不提交真实互动或 AI 请求。脚本 `captureScreenshots` 默认关闭，需保存新证据时可显式开启。已有截图位于 `output/playwright/`，不作为源码提交。

验证结果和环境警告见同目录的 `stellar-verification.md`。
