# 摘要同步修复与使用说明（4.0.8）

## 修复的问题

旧版“生成”只写插件的 `Summary` 记录，文章 `spec.excerpt` 的回写依赖前台 `POST updateContent`。回写遇到相同内容时返回 `success:false`，星港摘要框把它误判为没有摘要，造成首次显示、刷新后消失。批量同步还会按历史 `ai-summary-updated` 标记跳过文章，存库失败被转换成文本后仍记为成功。

新版将这三个阶段分离：

1. 发布事件或后台生成：读取当前发布版正文，调用 AI，保存摘要，再由后端回写文章字段。
2. 前台读取：`GET summaryContent/{postName}` 只读摘要，`available` 表示是否有可展示内容，不依赖是否发生写入。
3. 批量处理：补齐、仅回写和强制生成分别控制 AI 调用，提供真实进度统计。

不删除已有记录、不修改正文、不需要数据库迁移。生成和回写错误继续传播，不再用错误文本伪装成功。

## 升级后建议操作

1. 先备份 Halo 数据及旧插件安装包，然后安装新包，刷新页面以加载新版前端脚本。
2. 在“AI 设置”点击 **仅回写已有摘要（不调用AI）**，优先把原来已经存库的摘要补到文章字段。该操作不会补写草稿、黑名单或受保护的手动摘要。
3. 查看任务进度，确认 `failed=0`、`taskFailed=0`，且 `finished=total`。有失败时查看 Halo 服务日志里的文章名称及错误；AI 调用日志只表示模型阶段，不表示存库或回写一定成功。
4. 对一篇原先有成功图标但前台无摘要的文章，检查页面首次访问、刷新、离开后再进入、主题 AJAX 导航，均应保持摘要显示。
5. 如确实存在没有摘要记录的已发布文章，再选择 **补齐缺失摘要并同步**。换了模型或角色提示词才选择 **强制重新生成摘要**，会产生 AI 调用费用。

本次开发只验证本地代码、测试和构建，不代表生产环境已经升级或执行回写。

## 三种批量模式

统一接口：`POST /apis/api.summary.summaraidgpt.lik.cc/v1alpha1/syncAll?mode=<mode>`。

| mode | 设置页按钮 | 行为 |
| --- | --- | --- |
| `fill`（默认） | 补齐缺失摘要并同步 | 有当前发布版摘要则复用并回写；没有或新版记录版本过期则生成并回写。 |
| `repair` | 仅回写已有摘要（不调用AI） | 有当前发布版摘要则回写；缺失或已过期记录跳过，不调用 AI。 |
| `regenerate` | 强制重新生成摘要 | 重新生成并回写；仍遵守手动保护和黑名单。 |

只处理已发布且未删除的文章，旧成功标记不再是批量跳过条件。启动接口返回 HTTP 202，仅表示已接受任务；重复启动返回 HTTP 409，不重置正在执行的任务计数。

### 进度口径

`GET /apis/api.summary.summaraidgpt.lik.cc/v1alpha1/syncProgress` 返回：

- `total`：本轮列出的已发布、未删除文章数。
- `finished`：已处理文章数（成功、失败、跳过之和）。
- `succeeded`：完成同步处理的文章数，包括原本已一致、无需写入的文章。
- `failed`：生成、存库或回写失败的文章数。
- `skipped`：手动保护、黑名单、处理中撤稿，或仅回写模式下没有当前可用摘要的文章数。
- `generated`：本轮成功完成生成存库及回写处理的文章数，不是原始模型请求数；模型成功但存库失败仍计入 `failed`。
- `written`：本轮实际完成文章字段更新的数量。
- `running`：`1` 为运行中，`0` 为结束或尚未启动。
- `taskFailed`：任务级错误（例如列举文章失败）为 `1`，不能把 `total=0` 误认为成功。

设置页每两秒查询一次，最多查询 30 分钟；离开页面或轮询结束不会取消后台任务。进度只保留在插件进程内，重启或更新插件后不恢复旧任务，届时可再次执行补齐或仅回写。

## 手动摘要保护

- `summary.xhhao.com/enable-black-list=true`：不生成或回写，公开读取也不展示。
- `summary.xhhao.com/update-summary=true`：不生成或覆盖该文章的摘要。
- 无旧 AI 成功标记、`autoGenerate=false` 且 `excerpt.raw` 非空：视为手动摘要，默认不覆盖。
- 新回写会保存 `summary.lik.cc/ai-summary-hash`。之后手动修改文章摘要导致指纹不一致，即使旧成功标记还在也不再覆盖。
- 强制生成只强制更新 AI 管理的文章，不绕过以上保护。需要改回 AI 管理时，先在文章设置中启用自动摘要，或清空手动摘要，并解除显式保护标记。

### 旧数据的兼容边界

旧版只有 `ai-summary-updated=true`，没有指纹，无法可靠区分后来手动编辑的摘要与旧 AI 摘要。升级时有此标记的文章按旧 AI 管理数据兼容；**若曾手动改过这类文章，应先设置 `update-summary=true` 再执行批量操作**。没有成功标记的非空手动摘要则直接保护。

旧摘要记录没有发布版标记，会继续复用。新生成的记录保存 `summary.lik.cc/release-snapshot`；发布版发生变化时不展示或复用旧版摘要。生成期间重新发布会拒绝旧正文结果的回写，随后可使用补齐模式重试。

## 前台接口兼容

- 新前台使用 `GET summaryContent/{postName}`，返回 `success`、`available`、`summaryContent` 等字段，不触发 AI、不写文章。
- 旧前台的 `POST updateContent` 仍保留同形响应，但变为只读查询；后台任务负责回写，公开访问不再具备修改文章的副作用。
- 公开读取只提供已发布、公开、非黑名单文章的摘要；草稿和私有文章不会通过该接口泄露摘要。
- 前台渲染以 `available` 为准，并兼容旧版“摘要内容未发生变化，无需更新”的有效正文响应。缺失记录、空白文本和黑名单仍不显示为真实摘要。
- 单篇 `POST summaries` 生成成功后返回摘要文本；保护或未发布文章返回 HTTP 204；失败返回 HTTP 错误，不再返回 HTTP 200 的错误字符串。
- `findSummaries/{postName}` 仍保留后台记录查询语义与原有权限，不作为公开前台读取接口。
- 文章列表图标仅表示历史 AI 回写标记为字符串 `true` 且当前手动模式摘要非空，不表示正文与模型版本始终最新。

## 并发与限制

- 同一进程内同篇文章的在途生成请求合并，避免发布和批量任务重复调用模型。
- 回写只改摘要、状态摘要和插件注解，不修改正文、标题、标签等字段；遇到 Halo 乐观锁冲突，有限重试并重新 fetch 最新文章，不用旧版本覆盖其它修改。
- 模型调用成功、插件存库、文章回写是不同阶段。存库和文章更新不是跨资源事务；若后者失败，已保存的摘要保留，可以仅回写重试而不浪费模型调用。
- 批量互斥和生成合并都是进程内机制，未实现多实例分布式锁，不承诺多实例部署下无重复 AI 调用。
- 插件不会自动修复其它插件或编辑器随后对文章摘要字段的改写；新版前台仍可独立读取插件摘要记录。
